## 使用流程

選擇科別 → 查看診間／院內服務 → 追蹤取樣或設定到號通知。需要掛號時，由本人在「我的掛號」建立親友、選擇週曆並完成院方驗證；各項異動送出前仍保留原版確認步驟。

## 技術與資料

直接沿用原版 ClinicDashboard、ClinicTracking、PersonalAppointments、CSS 及資料映射；把原伺服器讀取路由整合到瀏覽器，直接呼叫允許跨站的醫院介面。GitHub Pages 不需 Node 或 Python 後端。

index.html 內嵌 CSS、React、JavaScript 與頁首圖示，不依賴 CDN 或外部字型。為完整保留原版 PWA 安裝、離線應用殼與 Service Worker 通知，另附 manifest.webmanifest、service-worker.js 及安裝圖示；全站約 1 MB。

**單檔邊界：** 主介面及程式集中在單一 HTML，但完整 PWA 需要同源獨立支援檔。若「單檔」被解讀為全站只能有一個檔案，就無法同時完整保留原版 PWA。本版依最新需求保留功能，未將它們刪除或偽稱只靠單檔即可安裝。

親友資料只在目前瀏覽器的 IndexedDB 保存；追蹤、通知與字體使用 localStorage。示範與真實紀錄分開保存。原本不同來源網址的本機資料不會自動移轉到 GitHub Pages。短效憑證與驗證碼不存入資料庫。

示範模式所有醫師、診次、掛號與驗證回應均為虛構，不連線院方，也不混入真實模式。

## 圖表與導覽修正

關閉符號於圓形按鈕內置中。示範追蹤的五筆完成紀錄依序為 3、7、10、4、8 分鐘，顏色為藍、藍、黃、藍、黃，最後一筆為灰色進行中。異常顏色僅依該筆結束時是否跳號或回叫判定，與異常事件及正常平均的篩選一致。平均虛線不再重複顯示文字，圖例獨立留白避免重疊。原有示範預設追蹤會升級成新的時間範例，真實追蹤資料不受影響。

## 一般模式連線與進度同步驗收

2026/10/18 晚間以一般模式實際連線院方，瀏覽器取得中央藥局目前號碼 75；公開排班取得 137 筆。四類服務均成功取得院方地點及進度回應：檢查 5 地點、抽血 3、領藥 4、櫃檯 3。當日心臟內科無門診診次；部分櫃檯回傳 --，保留院方原始無號碼狀態，不用示範值替代。數量與號碼僅代表當次回應。

同步機制：同一科別或服務地點共用一份公開進度回應，每 30 秒集中更新；手動重新整理、恢復連線或回到前景時立即重新取得。門診卡片、搜尋結果、追蹤選診與追蹤卡片、到號通知及當日掛號卡片共用資料。通知頁面隱藏時也繼續檢查已設定的當日診次。進度失敗時顯示無法取得，歷史分析資料可保留，但不冒充目前號碼。

這是定時查詢，仍受院方發布頻率、網路延遲、瀏覽器背景暫停影響；不宣稱與院方秒級即時一致。不同服務本來就有各自的號碼，只有相同科別、診間與時段才需一致。未代送真實掛號或取消，未輸入真實個資或院方驗證碼。

新增 10 項同步檢查，涵蓋同一資源合併請求、共同版本、手動與定時更新、前景恢復、重連、示範事件、失敗與恢復、進行中的舊回應防護、地點隔離與取消訂閱。瀏覽器已交叉核對門診／追蹤／通知／掛號顯示同一示範號碼，並驗證非目前科別的通知仍可觸發。
