# 候診通｜第五週 Vibe Coding 互動網頁作業

直接體驗示範：https://polarishunter.github.io/clinic-waiting-room/?mode=demo

以本人既有「候診通」作品為基礎，與 AI 討論後，另行製作適合 GitHub Pages 的單一 `index.html` 版本。原始桌面與伺服器專案不變。

## 規格書

### 一、動機與目標

看診時，使用者常需反覆確認叫號進度。我想製作繁體中文候診工具，讓使用者選擇科別、查看診間、追蹤自己的候診號碼，並在號碼接近時以清楚的視覺提醒呈現。

使用對象為想查看高雄榮總門診進度的民眾，以及體驗網頁互動功能的課堂使用者。

### 二、使用流程

1. 開啟網站，預設使用「醫院即時資料」。
2. 選擇門診分類、科別，查看診間與醫師。
3. 按「追蹤診間」，輸入候診號碼及提前提醒號數。
4. 在「我的追蹤」集中查看；接近號碼時卡片亮燈。
5. 休診時可主動切換「互動示範」，使用虛構資料驗收叫號互動。

### 三、功能與驗收條件

| 功能 | 具體規格 | 預期操作結果 |
| --- | --- | --- |
| 科別查詢 | 依醫院目錄顯示分類及科別 | 更換科別後只查詢對應進度 |
| 診間進度 | 顯示科別、診間、醫師、時段、目前號碼、末號及院方已報到候診欄位 | 無叫號或缺值顯示「—」，不捏造號碼 |
| 關鍵字搜尋 | 搜尋目前清單的科別、醫師、診間及時段 | 結果立即過濾，找不到時可清除搜尋 |
| 追蹤管理 | 每個模式最多 8 間，支援新增、修改、移除與全部清除 | 「我的追蹤」及計數同步更新 |
| 號碼提醒 | 候診號碼限 1～9999 整數，提前提醒限 0～100 整數 | 如目前 38、候診 44、提前 5，叫到 39 時卡片亮燈 |
| 過號狀態 | 目前號碼超過目標號碼時顯示文字 | 提示向診間確認，不宣稱使用者已完成看診 |
| 自動更新 | 真實模式可啟停每 60 秒更新，也可手動更新 | 頁面可見且未開啟設定對話框時更新；同時最多 3 個科別請求 |
| 更新異常 | 顯示錯誤，保留並標示該科別舊資料 | 舊資料不參與提醒判斷，可手動重試 |
| 無資料狀態 | 休診或尚未開診時如實顯示 | 可主動切換示範，絕不將示範當成真實資料 |
| 示範模式 | 虛構診間與醫師、叫號 +1、重設叫號 | 可在休診時測試完整互動；兩種模式紀錄分開 |
| 本機保存 | 使用 localStorage 保存診間與號碼設定 | 重整後仍可查看；真實追蹤跨台灣日期後清除 |
| 手機與鍵盤 | 響應式版面、表單標籤、可見焦點與原生對話框 | 手機可操作，鍵盤可開啟及取消追蹤設定 |

### 四、資料與提醒邊界

- 真實模式直接向高雄榮總公開網站介面取得資料；資料可用性依院方服務與看診時間而定。
- 示範模式均為虛構資料，在畫面明確標示；不自動替換真實資料。
- 提醒限網頁開啟時的畫面提示，不提供關閉網頁後的背景推播或系統通知。
- 不輸入身分證、生日、病歷或登入資料；不提供掛號、看診時間預測或醫療建議。
- 號碼差不是實際候診人數，叫號順序以院方現場為準。
- 本作品非院方官方網站。

### 五、技術與部署

所有必要 CSS、JavaScript、SVG 圖示均內嵌於 `index.html`。無外部字型、程式套件、圖片檔或建置需求，無伺服器路由；適用於 GitHub Pages 專案子路徑。

有網路時可查詢真實資料；離線時可手動切換示範功能。單獨下載 HTML 即可開啟示範，不代表真實資料必定能於所有瀏覽器的本機檔案環境取得。

GitHub Pages 設定：公開儲存庫，Settings → Pages → Deploy from a branch → main → /(root) → Save。只需根目錄的 `index.html` 即可運作；README 用於保存規格及協作說明。

### 六、AI 協作與調整過程

1. 先盤點現有作品，依「互動網頁、單一 HTML、GitHub Pages」要求比較可行題目。
2. 選擇候診通後，發現原版有自己的後端資料路由，因此先實測醫院的跨站許可及獨立瀏覽器查詢。
3. 確認瀏覽器可直接讀取科別與進度回應後，另製單檔版本，沿用候診工具概念與資料欄位。
4. 因驗證當日為星期日、醫院回覆無進度，加入明確標示的互動示範，讓休診時也能驗收。
5. 針對更新失敗、舊資料提醒、模式隔離、跨日設定與手機版面進行檢查與修改。實際通過項目以驗收紀錄為準。
